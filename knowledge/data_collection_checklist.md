## 1. 核心规则

### 1.1 数据可用性判定

```
有一个数据点
  │
  ├→ 来源是官方/行业协会（"可信单源列表"）
  │      ↓
  │   ✅ 单源即可 → 可用（进入评分）
  │
  ├→ 其他来源
  │      ↓
  │   ├→ ✅ 双源一致 → 可用（进入评分）
  │   │
  │   └→ ❌ 以下任一情况 → 视同无此数据
  │        ├ 只有一个来源
  │        ├ 两个以上来源但数据矛盾
  │        ├ 两个来源引用的是同一原始出处（非独立）
  │        ├ 来源为 Tier 3（转载/百科/个人博客）
  │        └ 来源类型不可识别/不可追溯
```

### 1.2 可信单源列表（无需双源验证）

以下来源本身具有公信力，其发布的原始数据**单源即可采用**：

#### 政府机构（Tier 1）
| 来源 | 适用数据 |
|------|---------|
| 国家统计局 | 宏观/行业产值、GDP、居民收支 |
| 海关总署 | 进出口数据 |
| 中国人民银行 | 金融数据、信贷结构 |
| 工信部 | 产业政策、产量统计 |
| 各省市统计局/经信委 | 区域行业数据 |
| 国家企业信用信息公示系统 | 工商登记、经营异常 |
| 中国执行信息公开网 | 被执行/失信 |
| 信用中国 | 行政处罚、红黑名单 |
| 中国裁判文书网 | 诉讼记录 |
| 证券交易所（深交所/上交所/港交所） | 上市公司公告、年报PDF |
| 巨潮资讯网（cninfo） | 上市公司公告（深交所指定披露平台） |

#### 行业协会（Tier 1/2）
| 来源 | 适用数据 |
|------|---------|
| 中国家用电器协会（CHEAA） | 家电行业主营收入、利润、运行趋势 |
| 中国汽车工业协会 | 汽车产销数据 |
| 中国电池工业协会 | 电池/储能行业数据 |
| 中国光伏行业协会 | 光伏行业数据 |
| 中国医药企业管理协会 | 医药行业数据 |
| 中国房地产业协会 | 房地产行业数据 |
| 中国连锁经营协会 | 零售/经销数据 |
| 各省市行业协会 | 区域行业数据 |

> ⚠️ **协会数据的使用限制**：协会发布的**原始统计数据**（主营收入、产量、利润等）单源可用，但协会报告中**引用的其他机构数据**（如协会报告中引用了AVC数据）仍需双源验证。

#### 商业研究机构（仍需双源）
以下机构即使业内知名，仍**不属于可信单源**，发布的数据需双源验证：
AVC奥维云网、GfK中怡康、产业在线、IDC、Counterpoint、券商研报、市场咨询公司

### 1.3 单源 vs 双源 使用规则总结

| 场景 | 规则 | 示例 |
|------|------|------|
| 来源在可信单源列表中 | 直接可用 | 中国家用电器协会说"2025年主营收入1.97万亿" → ✅ |
| 来源是商业机构 | 需双源独立一致 | AVC + GfK 都说"空调零售额X亿" → ✅ |
| 来源是可信单源，但数据过于关键（红线类） | 仍需双源 | 执行信息公开网说"无失信" + 第二个来源确认 → ✅ |
| 来源不明/无法追溯 | 永远不可用 | "据知情人士透露" → ❌ |

### 1.4 独立来源的定义

两个来源满足以下**全部**条件，才算独立：

| 条件 | 说明 |
|------|------|
| 不同机构/平台 | 企查查 vs 天眼查 ✅ / 企查查 vs 企查查 ❌ |
| 不同原始数据 | 券商研报A分析财报 vs 券商研报B分析同一份财报 ❌（同源） |
| 不同加工路径 | Wind 终端数据 vs 企业官网直接披露 ✅ |
| 非转载关系 | A新闻原创报道 vs B新闻转载A ❌ |

### 1.5 红线数据特殊规则

红线类数据（失信/税收违法/行政处罚等）在双源规则基础上，**至少有一个来源必须是政府公开信息**（Tier 1）：

```
红线数据判定
  ├→ 双源一致 + 至少1个Tier 1来源 → ✅ 确认触发/确认未触发
  └→ 不满足上述条件 → 不可判定，该企业评级不通过，需人工介入
```

红线判定不允许"数据不足跳过"——查不到足够证据确认，就视为无法通过自动评级。

### 1.6 官方来源强制规则（特定数据必须源自官方出处）

某些数据类型**不允许使用二手来源作为主来源**，必须追溯到企业/政府的官方原始出处。

| 强制类型 | 必须从官方取得的 | 可接受的官方来源 | 不允许的来源 |
|---------|---------------|----------------|-------------|
| **财务数据** | 营收、净利润、资产负债率、现金流、担保 | ① 交易所公告（巨潮/上交所/深交所/港交所）<br>② 公司官网投资者关系页面<br>③ 年报PDF原件 | ❌ 财经媒体转载<br>❌ 券商研报引用<br>❌ 第三方平台整理的财务摘要 |
| **经销商网络** | 经销商名单、门店数、区域分布、授权体系 | ① 核心企业官网（服务网络/经销商查询页面）<br>② 招股书/年报中披露的渠道数据<br>③ 官方公告中的经销商政策 | ❌ 新闻报道中的估算<br>❌ 行业报告的推算<br>❌ 经销商自己的宣传 |
| **品牌授权** | 授权状态、有效期、品牌层级 | ① 品牌官网授权查询入口<br>② 商标局公告<br>③ 品牌方官方授权声明 | ❌ 第三方标注的"品牌等级"<br>❌ 非官方的排行榜<br>❌ 旧闻中的授权信息 |
| **股权结构/关联方** | 实控人、股东、对外投资 | ① 国家企业信用信息公示系统<br>② 年报中的股权结构章节<br>③ 交易所权益变动公告 | ❌ 启信宝/天眼查摘要（可作提示，不可作判定依据）<br>❌ 百科词条<br>❌ 新闻中的股权描述 |
| **司法风险** | 被执行、失信、限高 | ① 中国执行信息公开网<br>② 中国裁判文书网<br>③ 信用中国 | ❌ 新闻笼统提及"有风险"<br>❌ 第三方平台未标注来源的风险计数 |
| **行政处罚** | 处罚决定书 | ① 信用中国<br>② 国家企业信用信息公示系统<br>③ 各监管部门官网（生态环境/税务/市场监管） | ❌ 新闻"据传""据悉" |

#### 官方来源验证流程

```
数据需求：格力电器2025年营收
  ↓
Step 1: 找官方出处
  深交所官网 → 格力电器2025年年报PDF → 利润表 → 营收1704.47亿 ✅
  ↓
Step 2: 找第二个独立来源做一致性验证
  巨潮资讯网 → 同一份年报 → 同源 ❌
  改：券商研报 → 独立分析后确认营收1704亿（不同加工路径）✅
  ↓
Step 3: 记录
  主来源：深交所公告（Tier 1）
  验证来源：XX证券研报（Tier 2，独立加工路径）
  双源独立一致 → ✅ 可用
```

#### 官方来源查找优先级

```
查找某个企业的官方数据时，按以下顺序定位：

财务数据：
  ① 搜 "[企业名] + 年报 PDF" → 深交所/上交所/港交所披露
  ② 搜 "[企业名] + 投资者关系" → 官网IR页面
  ③ 搜 "[企业名] 2025 年年度报告"

经销商网络：
  ① 搜 "[企业名] 官网 + 服务网络/经销商查询/门店查询"
  ② 搜 "[企业名] + 经销商 数量 + 年报 PDF"
  ③ 搜 "[企业名] + 渠道 网点 + 招股书"

司法风险：
  ① 搜 "中国执行信息公开网 + [企业名]"
  ② 搜 "信用中国 + [企业名]"
  ③ 搜 "site:court.gov.cn + [企业名]"
```

#### 过渡规则

在本系统未接入API（依赖WebSearch）的阶段：
- **财务数据**：无法直接访问深交所PDF → 标注"API未接入，数据暂缺"，该数据项不参与评分
- **经销商网络**：官网页面可通过WebFetch获取 → 先搜官网，再用WebFetch读取
- **司法数据**：政府公开网站可通过WebSearch + WebFetch获取

> ⚠️ **关键**：WebSearch阶段搜不到官方来源 ≠ "没有"。应标注"数据源不可及（未接入API）"，不是"无此数据"。

## 3. 搜索深度验证规范

### 3.1 最小搜索工作量

每个维度至少满足：

```
┌──────────────────────┬────────────────────────────────┐
│ 维度                 │ 最小搜索要求                    │
├──────────────────────┼────────────────────────────────┤
│ D1 行业景气          │ 3个方向 × 每个方向2+关键词      │
│ D2 品牌竞争力        │ 3个方向 × 每个方向2+关键词      │
│ D3 核企自身信用      │ 6个方向 × 每个方向3+关键词      │
│ D4 经销商体系健康度  │ 6个方向 × 每个方向2+关键词      │
│ 红线专项             │ 每个红线关键词3+表述            │
└──────────────────────┴────────────────────────────────┘
```

### 3.2 防漏检验证（"搜不到"不等于"没有"）

当搜索返回0结果时，执行以下验证流程：

```
Step 1：换3种表述重搜
  → 搜"被执行" → 0结果
  → 搜"被执行人" → 0结果
  → 搜"失信被执行人" → 0结果

Step 2：搜 positive control 确认搜索工具正常
  → 搜"中国执行信息公开网 被执行人" → 应有结果 ✅

Step 3：搜该企业 known positive 确认企业名称正确
  → 搜"企业名 成立 时间" → 如有结果 → 企业名输入正确

Step 4：确认搜索引擎没有因为格式/编码/特殊字符漏掉
  → 用企业全称搜索，而不是简称
  → 统一社会信用代码搜索（如有）

结论：搜不到 → 记录"搜索无结果，经防漏检验证确认"
```

## 5. 数据可用性与评分折算

### 5.1 维度有数据才能评分

| 维度 | 最低可用数据项要求 | 不满足时的处理 |
|------|------------------|--------------|
| D1 行业景气 | ≥2项 | 该维度不评分，权重并入D3 |
| D2 品牌竞争力 | ≥1项 | 该维度不评分，权重并入D3 |
| D3 核企自身信用 | ≥60%项 + 红线全部确认 | 不满足则转人工，自动评级不通过 |
| D4 经销商体系健康度 | ≥50%项（针对具体经销商） | 该维度不评分，权重并入D3 |

### 5.2 缺少数据维度的权重重分配

```
情况1：仅D1数据不足
  原：D1(15%) | D2(15%) | D3(40%) | D4(30%)
  折算后：D2(17.6%) | D3(47.1%) | D4(35.3%)

情况2：仅D2数据不足
  原：D1(15%) | D2(15%) | D3(40%) | D4(30%)
  折算后：D1(17.6%) | D3(47.1%) | D4(35.3%)

情况3：仅D4数据不足
  原：D1(15%) | D2(15%) | D3(40%) | D4(30%)
  折算后：D1(21.4%) | D2(21.4%) | D3(57.2%)

情况4：D1+D2+D4均数据不足
  → 仅D3有数据 → 等价于以D3为主判断，不产出完整评级
  → 结果标注"数据不足，仅以核企自身信用为参考"
```

### 5.3 不可评级的条件

以下任一条件触发，系统输出"数据不足以完成自动评级，转人工处理"：

1. D3（核企自身信用）可用数据项 < 60%
2. D3 红线检查有任意一条未完成确认
3. 四个维度中仅1个维度有可用数据
4. 所有可用数据项加总 < 总数据项的30%

## 使用流程

```
开始数据采集
    ↓
对每个维度执行搜索（按搜索模板库）
    ↓
对每个数据项执行双源验证
    ├→ 通过 → 记录可用
    └→ 不通过 → 标记弃用
    ↓
执行搜索深度验证（防漏检）
    ↓
执行红线强制确认
    ├→ 全部确认 → 继续
    └→ 未完成 → 转人工
    ↓
计算各维度数据完整度
    ├→ 满足最低要求 → 进入评分
    └→ 不满足 → 折算权重/转人工
    ↓
输出数据采集验证报告
```
