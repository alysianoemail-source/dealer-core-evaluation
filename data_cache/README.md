# 数据缓存

> 版本：v1.0 | 创建：2026-07-29
> 原则：同一数据源拉取一次、缓存复用、过期自动刷新

---

## 缓存策略

| 数据类型 | 文件位置 | 有效期 | 过期后处理 | 原因 |
|---------|---------|:--:|---------|------|
| 行业基准（年报） | industry_benchmarks/ | **6个月** | 重新调 iFinD EDB | 全行业统计滞后12-18个月，年际波动小 |
| 行业基准（月报） | industry_benchmarks/ | **3个月** | 重新调 iFinD EDB | 月度频率，滞后2-3个月 |
| 上市公司财报 | company_financials/ | **到下次财报季** | 季报/年报发布后刷新 | 财报有固定披露周期 |
| QCC 工商信息 | company_qcc/ | **1个月** | 重新调 QCC | 工商变更可能随时发生 |
| QCC 红线记录 | 不缓存 | **实时** | 每次都实时查 | 红线信息不能有任何延迟 |

---

## 写入规则

1. 每条缓存含 `fetched_at` + `expires_at` + `source`（可追溯）
2. 数据为空也写入（标记 `value: null, status: "unavailable"`），避免重复查询空结果
3. 来源标注清楚：iFinD 的具体指标ID / QCC 的查询参数

## 读取规则

1. 先查 index.json 确认是否有有效缓存
2. 有 + 未过期 → 直接用，日志记 `"来自缓存(拉取于YYYY-MM-DD)"`
3. 无 或 已过期 → 调 API → 写缓存 → 用
4. 过期期间 API 不可用 → 用过期数据 + 标注 `"数据已过期(过期于YYYY-MM-DD)"`
